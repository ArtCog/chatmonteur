# ChatMonteur — AI-видеомонтажёр для talking-head записей

> Делает работу опытного монтажёра — нарезка по смыслу, субтитры, графика, звук — через
> твоего агента (Claude Code / Codex), без таймлайна.

**ChatMonteur** («монтёр» — монтажёр) — расширяемая агентная монтажная студия для
**реальных talking-head записей** (влоги, туториалы, объяснялки). Кидаешь сырьё, говоришь
словами что нужно — агент гонит боевой пайплайн: транскрипт → паузы и оговорки по смыслу →
субтитры → моушн-графика → звук → цвет → рендер. Он монтирует записи, а не генерирует
видео с нуля.

Он **не переизобретает** движки. Он оркестрирует лучшие открытые инструменты —
[video-use](https://github.com/browser-use/video-use),
[hyperframes](https://github.com/heygen-com/hyperframes),
[auto-editor](https://github.com/WyattBlue/auto-editor),
[faster-whisper](https://github.com/SYSTRAN/faster-whisper), ffmpeg — и добавляет два
реально сложных слоя:

1. **Редакторскую голову** — [`skills/`](skills/INDEX.md): знания действующего
   YouTube-монтажёра (где резать, какой паддинг на склейке, когда зумить, насколько громко
   лежит музыка, чего не делать никогда) — написанные так, чтобы им следовал агент.
2. **Выстраданные правила корректности** — чтобы «одна команда» не выдавала битый ролик
   (нет зависших кадров, нет рассинхрона, нет убитого звука).
3. **Два гейта, которые умеют сказать «нет»** — то, что реально держит качество. Ниже.

## Два гейта

Агент, умеющий только соглашаться, отдаст тебе слабый монтаж с полной уверенностью в
голосе. Поэтому две проверки имеют право отказать, и ни одна из них не warning в логе,
который можно пролистать:

- **Гейт плана.** До того как сгорит первый кадр, визуальный план оценивается и
  отклоняется, если будет читаться как «просто убрал паузы»: участок больше 90 с без
  единого визуального события, текст на экране больше 60 % хронометража, повторяющиеся
  надписи, три одинаковых зума подряд.
- **Гейт файла.** Каждый рендер открывается заново, как его открыл бы посторонний: кадры
  на 10/35/65/90 % (не в начале и не в конце, где чёрное стоит по замыслу), звук
  проверяется по уровню на тишину и клиппинг, хронометраж сверяется с тем, что отдали
  энкодеру. Любая поломка останавливает выдачу и оставляет рядом отчёт `.qc.json`.
  Исправный механический черновик получает `continue_editing`; внутренний мастер
  с непроверенными правами — `review_rights`; только очищенный мастер — `ship`.

Оба появились после реальных провалов и оба — покрытые тестами наборы правил, а не эвристики,
закопанные в промпт.

> 🚧 **Статус: v0.1, делается открыто.** Механический пайплайн работает end-to-end
> за одной командой; полный агентный маршрут уже прошёл реальный ролик канала от
> восстановленного сырья до проверенного мастера.

## Быстрый старт

```bash
git clone https://github.com/ArtCog/chatmonteur && cd chatmonteur
./setup.sh                  # Windows: ./setup.ps1
chatmonteur tools           # что умеет и что готово
chatmonteur init 2026-demo --title "Мой ролик"       # явное создание проекта (необязательно)
chatmonteur edit raw.mp4 --project 2026-demo        # копия сырья → projects/2026-demo/raw/
                                                    # черновик → projects/2026-demo/renders/mechanical-draft.mp4
chatmonteur run sound --project 2026-demo --params sound-run.json
                                                    # запуск любой capability из JSON
```

Команда намеренно останавливается на технически исправном **механическом черновике**.
Дальше говори агенту: *«закончи монтаж — убери филлеры, добавь субтитры, графику и звук»*.
Он показывает обязательные гейты и только завершённый монтаж повышает до мастера.

`talking_head` принимает одну аудиодорожку. Если OBS-файл содержит отдельные mix
и microphone tracks, команда не угадывает нужную дорожку, а направляет агента в
документированный Branch B из `skills/cutting.md`.

## Зачем ChatMonteur

- **Умеет отказать.** Слабый план и битый файл останавливаются проверенным набором правил, а не отмечаются в логе.
- **Одна команда, а не copy-paste.** Настоящий CLI + агент-оркестрация вместо вставки промптов в IDE.
- **Глубина в talking-head.** Нарезка по смыслу, чистка филлеров, ловля оговорок, субтитры и графика в синхрон со словами.
- **Чутьё монтажёра, записанное текстом.** База `skills/` собрана на реальных опубликованных роликах, а не в сессии промпт-инжиниринга.
- **Бесплатно по умолчанию.** Локальный `faster-whisper` из коробки — без платного ключа. Премиум-движки (ElevenLabs Scribe) — опциональный апгрейд.
- **Кроссплатформенный энкод.** NVENC если есть, иначе fallback на libx264 / VideoToolbox / QSV.
- **Создан расти.** Реестр плагинов — новые тулзы и пайплайны добавляются без правок ядра.
- **Цифры, а не ощущения.** Каждый порог записан в [`engineering-facts.md`](skills/references/engineering-facts.md) — с обоснованием и с местом в коде, где он живёт.

## Как работает (talking-head пайплайн)

```
сырьё
  → нормализация (CFR, −14 LUFS)      не рассинхронить на VFR; выровнять уровень звука
  → резка пауз (по уровню звука)      auto-editor, залоченные пороги — слепа к смыслу, безопасна
  → транскрипт (word-level)           faster-whisper (локально) / ElevenLabs (опц.)
  → субтитры
  → цвет (LUT)
  → рендер                            результат с проверкой корректности

поверх — через агента (никогда автоматически):
  → умная резка                       АГЕНТ рассуждает над транскриптом, пишет EDL
    (филлеры, оговорки, дубли)        cut-plan, ты подтверждаешь → один точный проход
  → скрытие приватных данных          таймкодированные непрозрачные маски для ключей/личного UI;
                                      проверяются до любой выдачи preview
  → моушн-графика                     hyperframes-композиции, которые пишет агент
  → звук (музыка, ducking, SFX)
```

Слой решений за каждым шагом — в [`skills/`](skills/INDEX.md): читаемый, проверяемый,
напрямую подключается к Claude Code / Codex / Cursor.
