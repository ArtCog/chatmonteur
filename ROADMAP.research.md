## 1. Топ-20 к исполнению

### 1. `qc.py` — блокирующий гейт на финальном файле
**Что:** новый тул, последний шаг пайплайна. Проверяет готовый mp4 и **блокирует выдачу**, а не пишет warning.
**Параметры:** ffprobe → `duration < 1.0s`, дрейф от плановой длительности `> 25%`, `width<320 or height<240`, нет аудиопотока, битый контейнер. Кадры на **10/35/65/90%** длительности (не старт/конец — там интро/аутро). Чёрный кадр = **mean luma < 16/255** через `ffmpeg -vf "select=..,signalstats" -show_entries frame_tags=lavfi.signalstats.YAVG` (их файл-сайз-прокси `<2000 байт` **не брать** — хрупко). `volumedetect`: `mean_volume < -60 dB` → тишина, `max_volume > -0.5 dB` → клиппинг. Транскрипт финала vs исходный EDL-текст: `word_accuracy < 0.9` → issue.
**Ключевая переделка их логики:** у OpenMontage статус `fail` триггерится grep'ом по 6 фразам в тексте issues, и чёрные кадры/клиппинг/дрейф **не блокируют**. У нас — явный булев чек-лист: любой из {black_frame, clipping, no_audio, low_res, duration_drift, <4 кадров сэмплировано, subtitle coverage<0.95} = `status=fail`, `recommended_action=re_render`, пайплайн стоп.
**Тул:** новый `qc.py`; вызов в `pipelines/talking_head.yaml` последним шагом после `render`.
**Effort:** M
**Impact:** критично. Догфуд-ран v1 уже выдал мусор (галлюцинация «СИГНАЛ СМС», выкошено 28 из 50 с) — без гейта это повторится.

### 2. `transitions.py` — переходы между блоками
**Что:** три типа, не сорок. `cut` (concat demuxer `-c copy`) / `crossfade` (`xfade=transition=fade` + `acrossfade`) / `fade` (`xfade=transition=fadeblack` + `acrossfade`).
**Параметры:** offset для N клипов — накопительно: `offset_i = sum(dur[0..i]) - i*d`. Перед xfade **принудительно домешивать `anullsrc`** в клипы без аудио, иначе `acrossfade` падает. Дерево решений: та же сцена/тот же дубль → hard cut; смена темы → crossfade 0.5–1.0 с; интро→тело, тело→аутро → fadeblack 0.5–1.0 с; смена настроения → crossfade 1.0–1.5 с. Масштаб по хрону: <60 с → 0.3–0.5 с; 1–10 мин → 0.5–1.0 с; >10 мин → 1.0–1.5 с. **Дисциплина (жёсткое правило):** один primary-переход на 60–70% стыков + максимум 1–2 accent-типа на ролик. Разный переход на каждом стыке = запрещено.
**Анти-паттерн в код:** уход и вход анимируются в один и тот же момент T; никаких exit-анимаций до начала перехода (кроме последней сцены).
**Тул:** новый `transitions.py`, вызывается из `storyboard.py` при сборке блоков; hard cut остаётся дефолтом.
**Effort:** M
**Impact:** высокий — самый заметный признак «это не просто склейка».

### 3. Словарь ASR-коррекции + фильтр галлюцинаций
**Что:** два шага постобработки транскрипта.
**Параметры коррекции:** плоский YAML `assets/brand/asr_fixes.yaml`, ключи регистронезависимы. Алгоритм на уровне `words[].word`: отрезать хвостовую пунктуацию `.,!?;:'"` → сравнить lower() по словарю → заменить → **приклеить пунктуацию обратно**. Нет word-таймстампов → regex `\b...\b` IGNORECASE по тексту сегмента. Стартовый набор: `иимерсивный`, `клод код`/`код-код` → `Claude Code`, `гермес` → `Hermes`, `обс` → `OBS`, `опенроутер` → `OpenRouter`.
**Параметры фильтра:** если **>20% записей** транскрипта — токены `♪ \u266a-\u266f` или `�` → транскрипция **провалена**, ретрай моделью крупнее, не чинить. Выкидывать записи: пустой текст; только ноты; filler-регексп `huh|uh|um|ah|oh` длительностью **< 0.1 с**. Спаны слов `end-start < 0.05 с` — флаг «ненадёжный таймстамп» агенту (не чинить автоматически).
**Плюс гард:** запретить `.en`-модели при `language=ru` — суффикс `.en` **молча переводит** русскую речь на английский. `assert not model.endswith('.en') or lang == 'en'`.
**Тул:** `transcribe_whisper.py`.
**Effort:** S
**Impact:** высокий. Опечатка в бренд-термине в субтитрах — самый заметный любительский сигнал; стоит 40 строк.

### 4. Сегментация реплик по паузам, а не по счётчику слов
**Что:** сейчас `_break_lines`/`_fit_timing` — детерминированная упаковка. Добавить пороговый рез по речи.
**Параметры:** реплика рвётся на **границе предложения ИЛИ межсловном gap ≥ 150 мс ИЛИ лимите слов**. Альтернативная группировка (проверить обе на догфуде): склеивать токены, если разрыв между ними **< 1200 мс**. Наши ограничения сверху остаются и **не смягчаются**: CPL ≤ 39 (кириллица), CPS ≤ 17, min показ 0.83 с, не залезать в следующую реплику. Их дефолты (8 слов/42 символа/15 CPS) — мягче нашего стандарта, откатывать нельзя.
**Тул:** `subtitles.py`.
**Effort:** S
**Impact:** высокий — реплики начинают дышать вместе с речью, а не рваться посреди синтагмы.

### 5. Точные word-timestamps (stable-ts / WhisperX)
**Что:** faster-whisper даёт word-тайминги с дрейфом; варианты субтитров A (пословный fade), B (акцент), D (typewriter) на них держатся, и п.4 без них не работает.
**Параметры:** stable-ts поверх существующей faster-whisper-модели (large-v3, ru, GPU), режим verbatim (филлеры **не** нормализовать — это ломает интеллект-резку по D11). Выход в тот же JSON-контракт, что сейчас.
**Тул:** `transcribe_whisper.py`, флаг `--precise-words`.
**Effort:** M
**Impact:** высокий — предпосылка для 3 из 5 бренд-вариантов субтитров и для п.4.

### 6. Один LUT на весь таймлайн + канонический порядок фильтров
**Что:** зафиксировать в `color.py` цепочку и запретить per-clip грейд.
**Параметры:** порядок `normalize → colortemperature (WB) → colorbalance (тени/света) → curves (тон) → eq (контраст/сатурация) → lut3d (креативный LUT ПОСЛЕДНИМ)`. Интенсивность <1.0 через `split[a][b];[b]lut3d=...[g];[a][g]blend=all_mode=normal:all_opacity=X`. **LUT-интенсивность 0.6–0.8, никогда 1.0. Саturation ≤ 1.2 на кадрах с людьми.** Один LUT на проект, не переключать между сценами — именно это сшивает разнородный материал в один регистр. Их же анти-паттерн, прописанный дважды: per-clip грейд занимает в 10× больше времени и делает регистр **менее** консистентным.
**Тул:** `color.py` (+ `skills/references/effects.md`).
**Effort:** S
**Impact:** высокий — единый регистр читается как «цвет ставил человек».
**Честно:** их «защита кожи» (вектороскоп ~123°) — не код, а текстовая эвристика. Автоматики нет ни у них, ни у нас; пишем как правило в скилл, не как валидатор.

### 7. Continuity-сканер (замерший/мёртвый кадр)
**Что:** детектор участков, где картинка не меняется — это и QC-дефект, и **сигнал агенту, куда ставить вставку/зум**.
**Параметры:** сэмпл кадров раз в 1 с, даунскейл до 360p, grayscale, `mean(abs(diff))` между соседними. `< 0.5` → static; дисперсия `< 2.0` → animated_still (пан/зум по стиллу); иначе motion. Участок static **≥ 15 с** подряд → issue `dead_air_visual` с таймкодом. Тот же motion_score — как фильтр «мёртвых» стоковых клипов (`motion_min`).
**Тул:** новый `analyze.py`; выход в `qc.py` (гейт) и в `storyboard.py` (агент получает список «здесь скучно»).
**Effort:** M
**Impact:** высокий. Единственный численный CV-алгоритм, который у них реально работает, и он прямо про «выглядит смонтировано».

### 8. Главы (chapters)
**Что:** переиспользовать границы логических блоков, которые агент уже размечает по смыслу (PLAN, фаза ②) — второй раз их считать не надо.
**Параметры:** формат строки `0:00 - Название`. Первая глава обязана быть `0:00`, минимум 3 главы, каждая ≥ 10 с — иначе YouTube главы не включит. Название ≤ 40 символов. Выход `chapters.txt` + вклейка в `description.txt`.
**Тул:** новый `export.py` (п.9); источник — `storyboard.json`/блоки агента.
**Effort:** S
**Impact:** средний по картинке, высокий по восприятию канала.

### 9. `export.py` — пакет к загрузке + `credits.txt`
**Что:** локальная упаковка, без сети (аплоада не делаем).
**Структура:**
```
exports/<slug>/
  video/output.mp4, video/subtitles.srt
  metadata/metadata.json, description.txt, tags.txt, chapters.txt
  thumbnails/thumbnail.png | concept.json
  credits.txt
```
**Параметры:** title ≤ 60 символов; первые 150 символов описания — поисковые; 5–10 тегов, 3–5 хэштегов; thumbnail — **концепт JSON** (`{concept, text_overlay ≤5 слов, style_notes}`), не генерация. Явно переданный `subtitles_path`/`thumbnail_path`, которого нет на диске → **hard error**, не тихий пропуск. Валидация схемы **на входе в тул** (fail-fast на границе стадии), не на чекпоинте дальше.
**`credits.txt` — их незакрытый пробел:** конкатенация `creator + license + original_url` по всем ассетам манифеста. У OpenMontage атрибуция умирает в asset manifest и до публикации не доезжает. Мы MIT + используем CC0/CC-BY стоки — это не полировка, а обязательство.
**Тул:** новый `export.py`.
**Effort:** S–M
**Impact:** средний по картинке, критично по лицензионной гигиене.

### 10. Provenance с первого API-вызова в `stock.py`
**Что:** кандидат из поиска обязан нести `creator`, `license`, `source_url`, `source_tags` **до скачивания**, и эти поля без потерь текут в манифест и в кэш.
**Параметры:** источник с единой лицензией → константа (Pexels: `"Pexels License (free, no attribution required)"`). Источник с per-item лицензией (Openverse, Archive.org) → **читать реальное поле** `license`/`licenseurl`, угадывание по коллекции — только документированный last resort с честным хеджем. Логировать `rejected_picks` (`asset_id`, score, причина) — чтобы позже понять, почему проиграл второй вариант.
**Тул:** `stock.py`.
**Effort:** S
**Impact:** косвенный (питает п.9).

### 11. Каскад стиля: `brand.yaml` + схема + loader
**Что:** закрывает B9 из роадмапа. Стиль — валидируемый контракт, а не хардкод в каждом вызове.
**Параметры:** 4 уровня приоритета, снизу вверх: жёсткие дефолты → `assets/brand/brand.yaml` → per-video override → явный аргумент вызова. Секции: `visual_language.color_palette` (`#0B0F0E`/`#E8EDEB`/`#3CE5B0`), `typography` (Geist, размеры как множители), `motion` (`transitions[]`, `pacing_rules.min/max_scene_hold_s`), `audio` (`music_volume`, `ducking_threshold_db`), `overlays` (per-компонент bg/border/text/radius). Loader — **чистый Python, только `colorsys`+`math`**, без зависимостей: WCAG contrast ratio (4.5:1 body, 3:1 large), модульная типошкала. Плюс `overrides.scene_overrides` — до 20% сцен могут отклоняться от плейбука, но с обязательным полем `reason`.
**Тул:** `core/config.py` + новый `chatmonteur/brand.py`; потребители — `subtitles.py`, `overlays.py`, `inserts.py`, `motion_hyperframes.py`.
**Effort:** M
**Impact:** высокий — сейчас каждый тул красит по-своему, это и читается как самодеятельность.

### 12. Конструирование запросов к стокам
**Что:** один плоский запрос → мусор. Разделить на два поля и добавить каскад.
**Параметры:** на слот — `description` (богатое сенсорное описание для скоринга агентом: `<субъект>, <действие>, <окружение>, <освещение>, <текстура>`; без слов-намерений типа «момент сомнения») **и** `queries[]` — 2–3 фразы **по 5 слов и меньше** для keyword-поиска: literal, lateral, association. Категорийные слова (`home`, `tech`, `работа`) — запрещены, матчат всё и ничего. Fallback-каскад, идём пока не будет непустого результата: (1) точная фраза, (2) AND двух самых длинных не-стоп-слов, (3) OR трёх самых длинных. Приёмка агентом 1–5, брать ≥3; **не брать «лучшее из плохого»** — при всех отказах расширять запрос, не понижать планку.
**Тул:** `stock.py`.
**Effort:** S
**Impact:** высокий — попадание вставки в смысл видно сразу.

### 13. Байтовый кэш ассетов
**Что:** кросс-проектный кэш скачанных файлов. Закрывает заявленный gap «no asset caching».
**Параметры:** `~/.chatmonteur/cache/`, override через env. Ключ = `<source>_<source_id>` (стабилен между проектами). Попадание → **hard-link** (та же ФС) или `copy2` (кросс-диск) прямо в папку проекта, сеть не трогаем. Промах → качаем и `ingest()`. LRU-эвикция по `last_access_at` при потолке **20 GB**. Manifest — JSONL, перезапись атомарно `tempfile` + `os.replace`, блокировка `filelock` с таймаутом 60 с. Manifest указывает на несуществующий файл → тихий prune + считаем промахом.
**Не делаем (их же Phase 2/3, и правильно):** кэш эмбеддингов, кэш результатов поиска (риск устаревания), кросс-машинная синхронизация.
**Тул:** новый `chatmonteur/cache.py`, используется `stock.py`.
**Effort:** S–M
**Impact:** нулевой на картинку, высокий на скорость итераций (а итерации = качество).

### 14. Register smoothing разнородного материала
**Что:** правила сведения OBS-записи + скринкастов + стоков в один регистр.
**Параметры:** единый холст, приведение через **pad/crop, апскейл запрещён** (480p → 1920 = пиксельная каша; либо letterbox, либо осознанный кроп как решение). FPS-несовпадение → **дропать кадры равномерно, не интерполировать** (motion interpolation на смешанном материале выглядит ужасно). VFR-источники (скринкасты, телефон) → CFR **до** склейки, `-vsync cfr`. Codec mismatch → ffprobe-пробинг, реэнкод **только клипов-меньшинства**, не всей цепочки. Растягивание при смене aspect ratio запрещено.
**Тул:** `media.py` + `storyboard.py`.
**Effort:** M
**Impact:** высокий — «выпадающий» по регистру клип убивает впечатление сильнее, чем плохой переход.

### 15. Гард покрытия шрифта (RU+EN)
**Что:** самый ценный конкретный факт разведки для двуязычного канала.
**Параметры:** ловушка — скачивание шрифта с Google Fonts `css2` по «первому URL из ответа» молча отдаёт **один unicode-range сабсет**, часто без basic-latin или без кириллицы. Рендер не падает, лог пишет «шрифт загружен», текст молча падает на serif. Фикс: только цельный локальный TTF (`C:\MONTAGE\fonts\Geist-Bold.ttf` — уже так) + разовая проверка cmap: символы `АБВЮЯ` и `AZaz09` присутствуют в шрифте, иначе hard error на старте `subtitles.py`/`motion_hyperframes.py`. Никаких сетевых фетчей шрифтов во время рендера (ломает детерминизм).
**Тул:** `subtitles.py`, `motion_hyperframes.py` (общая функция в `media.py`), 15 строк на `fontTools.ttLib`.
**Effort:** S
**Impact:** предотвращает катастрофу молча.

### 16. Self-check субтитров
**Что:** после сборки — проверить, что субтитры действительно то, что сказано, и действительно исчезают.
**Параметры:** `coverage_ratio` = доля слов транскрипта, реально попавших в субтитры (порог блокировки **0.95**); `timing_drift_detected` — расхождение начала первой и конца последней реплики с аудио > 0.5 с; для анимированных вариантов (HyperFrames A/B/D) — перемотать таймлайн на `cue.end + 0.01` для **каждой** реплики и убедиться, что computed opacity = 0 (иначе реплики наслаиваются). Плюс автотест `_fit_timing`: ни одна реплика не пересекается со следующей, min 0.83 с, CPS ≤ 17.
**Тул:** `subtitles.py` + подаётся в `qc.py`.
**Effort:** S
**Impact:** средний, но убирает целый класс позорных багов.

### 17. Профиль энкода для текстоёмкого контента
**Что:** у скринкастов с кодом/UI текст рассыпается на дефолтном профиле.
**Параметры:** для screencast-сегментов **CRF 16–18** (верхняя граница качества диапазона), `-preset slow`, `-pix_fmt yuv420p`, `-movflags +faststart`, масштабирование `lanczos`, **не понижать разрешение раньше финального энкода**. Тяжёлые YouTube-настройки — только на финальном concat, не на каждой сцене (наше правило, не их).
**Честно:** их заявленные «text-preserving settings» — пустая декларация, конкретных параметров у них нет. Числа выше — наша эвристика, не заимствование.
**Тул:** `render.py`, новый профиль `screencast`.
**Effort:** S
**Impact:** средний — заметен только на кодовых кадрах, но там заметен сразу.

### 18. Декларативный tool-contract + auto-discovery + `events.jsonl`
**Что:** фундамент под доску (п.19) и под масштабирование скиллов.
**Параметры:** каждый `BaseTool` декларативно несёт `name/capability/provider/input_schema/output_schema/best_for/not_good_for/fallback_tools/agent_skills[]/user_visible_verification`. `agent_skills[]` — жёсткий список markdown-скиллов, привязанный к самому тулу (без центрального маппинг-файла: добавил тул → скилл автоматически виден агенту). Registry находит наследников через `pkgutil.walk_packages()` — добавление тула не требует правки ни одного другого файла. `BaseTool.execute()` сам аппендит строку в `events.jsonl` (однопоточная блокировка `threading.Lock`; между процессами не синхронизируем — однострочный `O_APPEND` рвётся редко, битую строку ридер пропускает).
**`user_visible_verification`** — не код, а обязательное поле-напоминание агенту: «открой кадр и посмотри глазами перед тем как одобрить». У них это единственная валидация текста в графике — OCR нет нигде.
**Тул:** `core/tool.py`, `core/pipeline.py`.
**Effort:** M
**Impact:** нулевой на картинку, обязательный для п.19.

### 19. Доска ревью (см. раздел 3)
**Effort:** L. **Impact:** не на картинку — на то, останется ли пользователь.

### 20. Auto-reframe 9:16
**Что:** кроп в вертикаль по лицу/активной зоне для Shorts.
**Параметры:** 5 кадров → bbox лица/области интереса → сглаженный трек центра (не покадровый — дёрганый кроп хуже статичного), safe-zone для субтитров снизу 20% кадра.
**Effort:** L
**Impact:** низкий **сейчас** — Артур снимает 16:9 voice-over, Shorts не в текущем плане. Делать только когда появится реальный запрос на вертикаль. Стоит в списке двадцатым честно: это заявленный gap, но не приоритет.

## 3. Интерфейс ревью: чему учит Backlot

**Главный архитектурный вывод, который берём целиком:** UI — это **read-only проекция файлового протокола**, а не API поверх агента. Агенту не нужно «уведомлять» доску. Он пишет те же артефакты, которые обязан писать по контракту пайплайна, а доска их читает. Ноль связности между агентом и UI.

### Что строим

**Технически (ленивая версия, отличается от их стека):**
- `python -m chatmonteur board <project>` — поднимает сервер на `127.0.0.1`, открывает браузер. Bind только на localhost.
- Сервер — stdlib `http.server.ThreadingHTTPServer`. **Без FastAPI, без watchfiles.** Один SSE-эндпоинт, который раз в 500 мс сверяет max(mtime) по папке проекта и шлёт `event: changed`. Браузер в ответ рефетчит состояние целиком — **никаких diff-патчей**, это то, что у них убирает половину сложности сервера.
- **Без БД и без состояния на сервере.** Всё выводится из файлов на диске при каждом запросе.
- UI — один `board.html` + один `board.js`, vanilla ES module. Без React.
- Каждый `json.load` в `try/except → None`; битый артефакт деградирует одну карточку, не роняет доску.
- Path containment: любой путь, взятый из артефактов (которые пишет агент), проверяется `Path(p).resolve().relative_to(project_dir)` — иначе отбрасывается. Чекпоинт не должен уметь протащить на доску произвольный файл с диска.

**Источники состояния (диск → элемент UI):**

| Элемент | Файл |
|---|---|
| Рельс стадий, статусы | `pipelines/*.yaml` + `checkpoint_<stage>.json` |
| Транскрипт с word-таймингами | `artifacts/transcript.json` |
| Cut-plan (что вырезано и почему) | `artifacts/edl.json` |
| Филмстрип вставок/зумов | `artifacts/storyboard.json` × кадры на `start` каждого бита |
| Панель дефектов | `artifacts/qc.json` (п.1) — маркеры прямо на таймлайне плеера |
| Лента активности, шиммер «идёт рендер» | `events.jsonl` (п.18) |
| Драфты и финал | `renders/*.mp4` |

### Чего у Backlot нет и что для нас главное

Их доска — витрина: смотреть можно, влиять нельзя. Нам нужно ровно обратное, потому что цель — «пользователь говорит агенту, а не правит файлы». Добавляем **ровно два канала записи**, оба — простые файлы, которые агент читает:

**1. Гейты (approve / changes requested).** Пайплайн уже имеет точки согласования: cut-plan, границы блоков, выбор варианта субтитров, storyboard. Кнопка в UI пишет `gates/<stage>.json` → `{"decision": "approved"|"changes", "comment": "...", "ts": ...}`. Агент на гейте блокируется на существовании этого файла. Это заменяет «скопируй JSON из чата и подтверди словами».

**2. Комментарий на таймкоде — killer-фича.** Пользователь тыкает в точку превью, пишет «здесь скучно, добавь вставку» / «этот кусок вырезать» / «зум лишний». Строка уходит в `notes.jsonl`: `{"t": 143.2, "text": "...", "ts": ...}`. Агент читает файл, соотносит таймкод с транскриптом и storyboard, вносит правку, перерендеривает. **Это и есть «взаимодействовать с агентом вместо ручного монтажа»** — пользователь показывает пальцем и говорит словами, всё остальное делает агент.

Плюс `decision_log` — **append-only**: правка решения пишется как «пересмотрено», предыдущая версия не затирается. Каждый ре-ран стадии архивирует прошлый чекпоинт в `history/`.

### Фазы

- **v0.1 (M):** рельс стадий + плеер драфта + панель QC с маркерами дефектов на таймлайне + лента событий. Read-only. Уже полезно: видно, где агент накосячил, без пересмотра всего ролика.
- **v0.2 (M):** гейты с кнопками + `notes.jsonl` на таймкоде. Здесь продукт перестаёт требовать текстового пинг-понга.
- **v0.3 (S):** филмстрип storyboard с превью-кадрами вставок, diff EDL «было/стало» между ре-ранами.

Из их «библиотеки проектов», replay и cost-meter в v1 не берём ничего: проектов у нас единицы, стоимость нулевая (free-first), replay — украшение. Вместо cost-meter показываем время стадий из `events.jsonl` — это реально болит.
